# 肥鱼饭盒（dsh-feiyu-lunchbox）

左栏「肥鱼饭盒」入口 + 一个大型悬浮窗「货架」。把带标签词的图片拖进货架，
按 品牌 / 品类 / 规格 排货，标价（Tokens）/ 数量（份）写在白板上，勾选「挑选数量」
形成一批「购入美味」，最后把它拖进会话投喂给肥鱼。

## 安装

1. 到 [Releases](https://github.com/SeaWindyCN/dsh-fatfish-lunchbox/releases) 下载最新的 `dsh-fatfish-lunchbox-v*.zip`，
   解压到一个固定目录，例如 `D:\DSH\plugins\feiyu-lunchbox`（解压后这一层里应该有 `package.json`、`client.js`、`index.js`）。
2. 让 DSH 认识它，二选一：
   - **推荐**：用 Harness 的 `plugin_manager` 工具，`action: "install_bundle"`，`target` 填解压后的绝对路径（它会把目录 link 进 profile 并记进 `dsh.profile.bundles`）；
   - 手动：把目录复制或 link 到 `%USERPROFILE%\.dsh\profiles\<你的 profile>\node_modules\dsh-feiyu-lunchbox`，
     再把 `"dsh-feiyu-lunchbox"` 追加进该 profile `package.json` 的 `dsh.profile.bundles`。
3. **重启 DSH 桌面端一次**——组合树只在启动时按 bundles 生成，热改不会加载新插件。
4. 左栏出现饭盒图标就是装好了；点开看窗口底栏最左的版本号，应与本次 Release 的 `v1.7.19` 一致。

> 仓库里没有 `test/` 目录：那套离线测试脚本是本机开发用的（里面写死了本机的绝对路径），留在开发机上，不随包发布。

## 功能对照

| # | 需求 | 实现 |
|---|------|------|
| 1 | 悬浮窗 | `shell.overlay` 上的一扇可拖动大窗口；左栏 `sidebar.panellist` 图标点开；同时注册 `main` 页兜底（万一宿主先切了面板，会立刻返回对话并弹窗） |
| 2 | 进货 | 「进货」按钮或把图片拖进窗口；文件名含标签词自动归位，缩略图统一 4:3 裁切、按网格码放；标题栏 `?` 里有进货/排货/换货/投喂四段说明 |
| 3 | 排货 | 默认 / 品牌 / 品类 / 规格 四种排法，分组显示，词库可扩展（设置里加词） |
| 4 | 换货 | 选中素材后「清理选中」（二次确认）淡出掉落；把新图拖到已选中的素材上，旧货同样淡出掉落再上架新货 |
| 5 | 切换货架 | 7 个标签各自一页；上方标签页或「切换货架」按钮循环切换 |
| 6 | 货源 | 本地检索 + 预留外部货源接口 `window.FEIYU_LUNCHBOX.registerSourceProvider(fn)` |
| 7 | 详情 | 每张素材下方白色白板：标价（Tokens）、数量（份）各占一行，输入框字号放大；整窗字号可在工具栏或设置里调 |
| 8 | 设置 | 闲暇时光=零食+饮料、圆满完成=米饭+炒菜+炖菜+炖汤、心情舒畅=特殊；映射与词库均可增补 |
| 9 | 选货 | 挑选数量步进器，实时汇总 Tokens 与份数，整批叫「购入美味」 |
| 10 | 钱包 | 界面右下角的大号「已投喂 N 元」，点开是明细面板（累计购入 / 累计已投喂 / 本单），充值等后续深化 |
| 11 | 识别交互 | 把「购入美味」拖到任意位置松手（整屏会亮起「松手投喂」接收区，盖在窗口上方，窗口里手滑松手也算）或输入框下方的投喂条，也可以点「投喂这个会话」；按标签所属时光与数量生成对话，并扣库存、记钱包 |

> 拖到对话区时整屏铺接收区不是装饰：如果让浏览器把拖拽的纯文本粘进输入框再回车，
> 消息虽然长得一样，但不会扣库存、不会记钱包、挑选数量也不会清零。接收区接管落点后走的是
> `sessions.retain → session.prompt`，这三件事才会一起发生。
>
> 1.2.1 起接收区挂到 `document.body` 上、但只做视觉提示（`pointer-events:none`）；落点由
> `dragstart` 里挂在 `document` 捕获阶段的 `dragover/drop` 接管：拖拽期间无条件拦下
> dragover（否则浏览器根本不会派发 drop），松手必进 `handleBatchDrop`。
> 自定义 MIME 被浏览器吃掉、只剩 `text/plain` 时，会按文案对回上一批，照样扣库存记账。

## 1.3.1 修正（按用户反馈）

1. **图模式下货架区太亮 → 改深色半透明**：`[data-skin=image]` 时标签栏 `rgba(18,14,10,.34)`、
   工具栏同色、`.flb-body` `rgba(14,11,8,.46)`、托盘 `rgba(18,14,10,.72)`，
   卡片改成 7% 白 + 浅描边，标题/文字转浅色。背景图能透出来，字也仍然看得清。
   白板（标价 / 数量）保留浅色，方便读数字。
2. **字号控件无效 → 根因是取整**：0.8–1.6 的缩放比被 `num()` 四舍五入回 1，
   所以点 `A+` 数字不动、字也不动。加了 `flt()`（保留小数）替换所有 `num(st.fontScale)`；
   同时不再用 `calc(Npx * var(--flb-fs))`，改成**渲染时按比例算好像素值**
   （`cssFor(scale)` 把 CSS 里每条 `font-size:Npx` 换成 `(N*scale)px`，按比例缓存），
   只依赖字符串替换，不依赖自定义属性解析。
3. **透明 PNG 不要棋盘格/角标**：删掉 `.flb-thumb-alpha` 的棋盘格与 `.flb-alpha-flag`（「透明」角标），
   缩略图和容器都改成 `background:transparent`，透明处直接透出货架与背景图。

```
闲暇的时间就好好的款待自己吧，主人请你吃点“米饭*2”，继续加油=w=
```

## 投喂没反应怎么查（1.1.0 起）

每一步都留了痕，而且界面本身会说话：

0. 1.1.1 起：取会话服务只走 `ctx.get('sessions')`（可选依赖的官方口子），不再直接读
   `ctx.sessions`。没在 `inject` 里声明就访问 `ctx.sessions` 会抛异常，而抛点正好在弹提示之前，
   表现就是「点了完全没反应」——所以整条投喂链路现在包了 try/catch：同步抛错也会变成一次带阶段的失败提示。
   1.1.2 起再补一条：会话如果已经打开着，先用 `sessions.binding(id)` 拿到现成的 SessionBinding 直接发，
   绕过 `retain → ready` 这条最容易卡住的路；自检里的 `feed-direct` 行会写 `binding` / `hasSession`。
1. 点「投喂这个会话」后立刻会弹「正在把这批送到对话…」；失败时托盘下方常驻一行红字
   `上次投喂失败（阶段）：原因`，阶段是 `no-service` / `no-session` / `retain` / `ready` /
   `no-submit` / `submit` / `prompt` / `timeout` / `throw` 之一。
2. 会话 id 没拿到时，托盘右侧会写「先打开一个对话，投喂条才连得上会话」。
3. 等不到响应不会静默：等会话就绪 8s、提交消息 10s，超时会明确报 `timeout`。
4. 需要更深的原因时，读 `localStorage['dsh-feiyu-lunchbox.diag.v1']`：`env` 行记录
   `ctxSessions` / `ctxGet` / `lookup` / `sessionId` / `dock` / `api`（sessions 服务暴露的方法名），
   `submit` 行记录走的是 `prompt` 还是 `beginSubmission`。
5. 拖动时整屏接收区如果卡住不走，点一下它就会收起，不会一直吞点击。

## 拖拽投喂为什么点了没反应（1.2.1）

自检里只有 `drag-start`、紧跟着 `drag-stop`，没有任何 `drop` 行 —— 拖起来了，但浏览器
从头到尾没派发 drop。原因是 HTML5 拖拽的规则：**只有当 dragover 阶段被 `preventDefault()`
之后，松手才会产生 `drop` 事件**，否则只有 `dragend`。而旧版的 dragover 只在
`dataTransfer.types` 里能看到自定义 MIME 时才拦 —— 一旦 `setData` 被浏览器或扩展吞掉、
types 里只剩 `text/plain`，dragover 就一律被忽略，于是「拖了半天，松手什么都没有」。

1.2.1 把这条链路改成命令式：

1. `dragstart` 里直接 `document.addEventListener('dragover'|'drop', …, true)`（不经过 React
   状态与 effect，不存在「状态更新丢了监听就没了」）；`drop` / `dragend` 里撤掉。
2. 拖拽期间**无条件** `preventDefault` 掉每一次 dragover —— 这段时间页面里只可能有我们
   自己这一批「购入美味」，所以松手必定产生 drop，必定进 `handleBatchDrop`。
3. 整屏接收区（`flb-catcher-portal`）降级为**纯视觉提示**：`pointer-events:none`，只负责
   「亮起来告诉你可以松手」，不再承担接事件 —— 它也不会在拖拽中途改变命中的元素、把拖拽搞崩。
   它仍然 portal 到 `document.body`，否则会被 `shell.overlay` 裁掉、铺不到对话区。
4. `dragstart` 里不再同步 `store.set`：同步重渲染会把拖拽源节点换掉，Chromium 会直接取消
   这次拖拽；接收区延后 120ms 再显示。
5. 自检新增 `drag-data`（dragstart 时 types 里到底有没有自定义 MIME）、`drag-over`（第一次
   dragover 的 types）、`drag-drop`（真的收到 drop 了）、`drag-end`（dragend 的收尾）。
   只要有一条 `drag-drop`，就说明浏览器这一侧已经通了，问题只可能在后面的 feed 分支。

松手时如果指针还在货架窗口里，算「放回去」：只收起接收区、不投喂、不扣库存。

## 1.3.2 新增（按 m02682 六条）

1. **顶栏副标题**：原来显示「货架 · 饮料 · 0 件」，现在固定一句「世间美味与你同享，照顾好可爱大肥鱼」；
   件数信息挪进 `title`（鼠标悬停才看），标签页上的数字仍然在。
2. **外部图片拖拽只认货架窗口**：以前把图片拖到对话区松手，浏览器会把它交给聊天输入框（变成往对话里传附件）。
   现在 `apply` 里挂了 `installFileDropGuard()`——在 `document` 捕获阶段先判断落点，不在 `.flb-window` 里就
   `preventDefault` + `stopPropagation`，并提示「图片请拖进肥鱼饭盒窗口里再松手」，自检记 `file-drop-blocked`。
   窗口关着 / 收起时不管，免得误伤正常的对话附件。
3. **深色详情面板**：图皮肤下，钱包详情和说明详情（`.flb-panel`）改用和托盘同款的 `rgba(18,14,10,.72)` 深底 +
   浅色文字；统计格、虚线行、普通按钮一起跟着转深，浅色背景图不再和面板抢对比度。
4. **空态居中**：`.flb-body` 改成 flex 列、`.flb-empty` 用 `flex:1` + `justify-content:center`，
   空货架的图标和两行文字落在货架区正中间，不再挤在顶部。
5. **元 / 点菜 / 不挡数字的加减键**：白板标价单位 `Tokens` → `元`（托盘合计、钱包明细、投喂提示一起改）；
   「挑选」→「点菜」；点菜的加减键改小（1.4.0 起直接放在「数量」那一行右侧，见下一节）。
6. **切换货架转场**：`setTab` 记下方向（往后翻 `tabDir=1`，往回翻 `-1`），内容区换成 `key=当前标签` 的
   `.flb-swap`，用 `flb-swap-right` / `flb-swap-left` 两条关键帧做位移 + 淡入；标签栏本身不动。

## 1.4.0 新增（按 m02964 八条）

1. **白板数字居中、加减键挪到旁边**：`数量` 那一行变成 `数量 | 数字（居中、下划线在中间） | 份 | − +`，
   加减键是 17px 的小方块，贴在行末，不再压住下划线；没点菜时行末是一个虚线小按钮「点菜」。
2. **勾选换货**：每件货右上角有小方框（`✓`），可以多选；换货只清理勾中的，不再依赖「点菜」状态。
   从外部拖一张新图砸在某件货上「以旧换新」的老玩法保留。
3. **拖动排序**：拖动缩略图（左半边落在目标前、右半边落在目标后）可以把货按自己的顺序摆，
   摆完会自动切回「默认」并把顺序写进存档；同时**去掉了从货架直接把货拖进会话**，
   现在投喂只有托盘上的「拖入会话投喂」和「投喂这个会话」两条路。
4. **字号进上栏、查询靠右、排货多「价格」**：字号 `− 100% +` 搬到标题栏、换肤键左边；
   货源搜索因为 `margin-left:auto` 留在工具栏最右；排货多一档「价格 ↑ / ↓」，同价按中文排序。
5. **悬浮窗独立于会话**：窗口整体 portal 到 `document.body`，不再寄生在会话容器里，
   会话最小化 / 切走也不会把货架一起收起来（方便从资源管理器往窗口里拖图）。
6. **清空钱包**：设置 → 数据，红色「清空钱包」按钮，点一次变成「确定清空？」，再点才把已投喂与明细归零。
7. **转场 1 秒、移出四分之一**：`flb-swap-*` 改成 `1s`、位移 `translateX(±25%)`，
   翻页时旧货先滑走四分之一、新货从另一侧慢慢淡进来。
8. **七套台词**：`TAG_SENTENCE` 按标签给话（零食/饮料 在闲暇时光，米饭/炒菜/炖菜/炖汤 在圆满完成，
   特殊 在心情舒畅），一批里有多个标签时分多行，每行都是 `【时光】…“素材名*数量”…=w=`。
   例：米饭 → 「这次的工作完成的很好，主人给你蒸了点“米饭*2”，再接再厉=w=」。

## 改文件时的两个坑

1. **`package.json` 不能带 UTF-8 BOM**。带 BOM 时宿主读它报
   `Unexpected token '﻿', "﻿{…" is not valid JSON`，整个 bundle 在插件列表里变成
   `availability: missing`、`rows: []`——侧栏图标、悬浮窗、投喂条全都不存在，
   而界面上没有任何提示。用编辑器另存为「UTF-8（无 BOM）」，或用 node 重写：
   `fs.writeFileSync(p, s.replace(/^\uFEFF/, ''), 'utf8')`。
2. **改了 client.js 不刷新页面就不会生效**。服务端会重建（`/plugins/events` 里的 `rev` 会变），
   但页面内存里还是旧模块；关掉重开应用或在页面里按 `Ctrl+Shift+R` 才会换掉。
   判断页面里跑的是哪一版：窗口底栏右下角的版本号，或 `localStorage['dsh-feiyu-lunchbox.load.v1']`
   （1.1.2 起每次执行都会写一条）。
3. **中文文件不要过 PowerShell 的文本往返**（`Get-Content -Raw` + `Set-Content`/`-replace` 再写回）：
   PS 会按 ANSI 解码 UTF-8，写回时无法解码的字节变成 U+FFFD，整篇乱码且不可恢复。
   改 `.md`、`client.js`、测试脚本一律用编辑器的 read/edit/write，或在 node 里按 utf8 读写。

## 1.7.20 性能修正（按 bug检查.txt 的反馈报告）

商品一多就卡，根子不是某个函数慢，是「任何一次全局写入都重画整面货架」。这一版按报告的
P0/P1/P2 顺序做了下面这些，行为不变、手感变了：

- **卡片只吃 props，并用 `React.memo` 包住**（`ItemCardMemo` + `cardProps`）：
  原来每张卡自己订阅全局 store，N 张卡 = N 个订阅者，点一下「点菜」全树重画；
  现在缩略图 / 是否勾选 / 拖动状态都由父层算成原始值传下去，改一件只重画那一件
  （报告实测 300 件时一次操作从 86 ms 降到 2~3 ms）。
- **拖动窗口 / 拉边框不再每帧写 store**：过程中用 `paintWinRect()` 直接改元素的
  `left/top/width/height`（rAF 合并），松手才 `store.set({ win })` 并落盘。
- **贬值按秒结算**：`beat.dipAcc` 攒满 1 秒才调一次 `dipStep()`，不再每 200 ms 写一次 store。
- **`onDragEnter` 补了状态守卫**：原来 dragenter 随子元素冒泡，拖一次文件能重画几十上百次。
- **框选**：从卡片 / 按钮 / 面板上按下不再起手（原来每次按下都要 `querySelectorAll` +
  逐个 `getBoundingClientRect`）；拖动时矩形按 rAF 合并。
- **进货攒批提交**：每 12 件合并一次 `store.set`，收尾再 flush，不再「一张图一次全量重渲」。
- **缩略图最长边 560 → 320**（卡片里才约 100 px，2x 屏 200 px 就够）；
  `<img>` 加 `loading="lazy"` `decoding="async"`。
- **`detectAlpha` 一次读回整张图**再抽样：原来逐像素 `getImageData(x, y, 1, 1)` 最多 2304 次读回。
- **CSS**：去掉每张卡常驻的 `will-change:transform`（几百个合成层）改成 hover 时才提层；
  卡片加 `content-visibility:auto; contain-intrinsic-size:auto 260px`，屏外卡片跳过渲染。
- **改标价 / 数量时的「叮」**压到 400 ms 一次，不再每按一个键响一下。

## 1.7.22 修复（按反馈：上传完美食包窗口就不见了）

- **根因**：1.7.21 给货架加了「一屏一屏渲染」的三个 hook（`useState` / `useRef` / `useEffect`），
  但它们写在「空货架提前 return」之后。空货架那次渲染根本没调 hook；美食包一上传，商品出现，
  同一组件突然开始调 hook —— React 抛
  `Rendered more hooks than during the previous render`，槽位整块被卸载。
  窗口因此消失、再点图标也唤不回；而计时心跳是模块级的，所以「获得券」的音效还在响。
- **修法**：hook 全部挪到空态判断之前，每次渲染顺序完全一致（空态分支改到两个 effect 之后）。
- **加了一层兜底**：货架主体用 `safe()` 包进 ErrorBoundary，以后任何渲染错误都只显示一条红字
  「这块内容渲染出错了（其它功能还在）」+「再试一次」，并把 `render-error` 写进自检，不会再把整窗弄没。

## 1.7.22 的验收要点

1. 强刷到 `v1.7.22`。
2. 切到一个**空货架**（比如刚换的标签），点「上传您准备的美食包」选一个文件夹：
   窗口应该留在原地、素材逐件出现，而不是整个消失。
3. 如果哪天真崩了：窗口里会出现红条而不是消失，点「再试一次」能回来。

## 1.7.24 修正（按 m07435）

1. **收起条也摆手柄**：`resizeHandles` 不再在 `st.minimized` 时清空，

## 1.7.25 修正（按 m07499）

上一版为了「别拉出空白页」会在第一次位移时自动展开——结果变成「拉一下就展开页面」。现在改成：
1. `startResize` 里 `miniOnly = !!st.minimized`：收起态拉边框**只改宽度**，绝不 `minimized: false`。
2. 收起态绘制只写 `left/top/width`（高度是 `auto`），拖完提交时用 `h: num(store.state.win.h)` 保留展开后的高度。
3. 竖向把手（`n`/`s`）在收起态按横向处理（`effDir = dir + 'e'`），所以上下边框也能拖，但只改宽。
4. 手柄提示在收起态改为「拖动边框：调整这条窗口条的宽度」。

## 1.7.26 修正（按 m07559）

批量改动份数时，每件都会触发一次「叮」（`setPick` 里 `after !== before` 就响），
所以框选多件一起放进「购入美味」后一键清空，会变成 N 声叠成一片噪音。现在加了一个静音窗口：

```js
var quietUntil = 0
function quietly(fn) { quietUntil = Date.now() + 120; try { return fn() } finally { quietUntil = 0 } }
// setPick 里：
if (after !== before && Date.now() > quietUntil) playSound('ding')
```

托盘「清空」、套餐「点菜一整份」、套餐「撤」都改成 `quietly(...)` 包住批量循环，收尾自己响一声。
单件点菜/减份仍然每次一声，不受影响。

## 1.7.27 修正（按 m07599）

两件事一起改：

- **判定区域 = 整条窗口条**：`onHeadPointerDown` 原来写着 `target.closest('[data-no-drag], .flb-rs')`，
  鼠标落在标题、上传口、按钮上时直接返回，只能从缝里拖。现在只让开四个边的拉伸手柄（`.flb-rs`），
  整条都能起手。
- **拖动只负责拖动**：`paintWinRect(r)` 会把 `height` 一起写进内联样式，而收起成一条时高度本应是
  `auto` —— 一拖就把展开高度（比如 700px）写回去，看着就是「自己弹开了一块空白」。现在
  `paintWinRect(r, keepHeight)`，收起态拖动只写 `left/top/width`；松手提交时也保留原来的
  `h`，不会把收起条撑高。
- 附带：真拖动过之后 0.22 秒内的点击会被标题栏的 `onClickCapture` 吞掉，免得「拖着拖着顺手把窗口关了」。
